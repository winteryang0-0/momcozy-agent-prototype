发现与最少修正
C01 / P2 / 实现-规范不一致：实际按压曲线仍为release。
定位：style.css 的 button 定义 transform 180ms var(--release)，button:active仅改 transition-duration:80ms，没有覆盖 transform 的 timing-function。因此实际按下使用80ms release(.2,.8,.2,1)，与文档/JSON/曲线台 press(.2,0,0,1)不一致。
修正：active 状态显式绑定80ms var(--press)，抬起保留180ms var(--release)。验证 computed transitionTimingFunction 与一次实际按压/释放。

C02 / P2 / 平台适配不一致：Android样张同时缩放与ripple。
定位：全局 button:active scale(.98)覆盖Android手机按钮；app.js又在Android pointerdown添加ripple。STYLE_SPEC 06明确Android标准组件不叠加自定义缩放。
修正：Android样张的phone按钮按压取消scale，仅保留本地示例ripple；曲线台可继续演示跨端自定义控件曲线。原生反馈仍需原生实现，不因HTML修正宣称原生验收。

C03 / P2 / 关键说明偏小且规范映射不透明。
定位：style.css 的feedback strong为14px、feedback p为12px，reassurance为12px；STYLE_SPEC给iOS说明15/21pt、Android14/20sp。五张图中的状态恢复说明明显比字段与动作文字细小，尤其390样张；这是关键任务信息，不宜全部视作元数据。
修正：状态标题建议16px，状态帮助文案至少14px（iOS候选可15px），明确HTML到平台排版的展示映射；重新检查长同步失败说明是否推动布局但不与底部操作层重叠。字号属于设计判断，不是本轮可访问性不合规认定。

C04 / P2 / Edit禁用原因不够明确。
定位：app.js在unknown/local/syncFailed等状态禁用Edit；现有状态说明只要求核验或说明同步情况，没有解释编辑为何不可用、如何恢复。STYLE_SPEC承诺“按钮不可用必须同时让原因可见”。对应暗色unknown与亮色syncFailed截图中Edit只变灰，仍保留“You can update this later.”。
修正：为这些实验状态提供一句明确说明，例如先核验/完成同步再编辑；或在实验室说明区明确这是未定义冲突规则下的临时禁用。不要将候选实验约束包装成正式业务限制。

C05 / P3 / 机器规范中的未知核验与再次保存语义混用。
定位：design.json DEMO-UNKNOWN为unknown -> saving -> synced；app.js先showState('saving')再手改为Checking save status。因此可见文案正确，但data-state/机器流程看起来像再次保存。
建议：新增checking状态或为复用处理态明确operation=check，保持文案、状态ID、流程一致。属于机器规范可读性问题，不是已证明实际重复提交（此处无真实API）。

C06 / P3 / state曲线台作用对象与规范不一致。
定位：app.js实际状态更新仅动画statusSymbol，符合文档；但curve=state时将opacity .55→1应用于整个motionTile，连示例文字一起淡入。文案说“图标淡入，关键状态文字立即更新”。
建议：curve=state仅对演示图标应用淡入；或明确曲线台是通用曲线示意，但不宜用关键文字淡入示范与规范相反行为。
