# 内测优化与设计变更管理

## 分支与版本

| 分支或标记 | 作用 |
| --- | --- |
| `main` | 当前已确认高保真基线；原型变更需通过新基线流程进入 |
| `baseline/B-MOMCOZY-20261022-R27` | 当前基线提交的版本标记；流程禁止重写 |
| `codex/internal-test` | 内测候选与变更记录；当前 Onboarding 重构从这里开始 |
| `codex/change/<主题>` | 后续单项优化；从内测分支创建，PR 合回内测分支 |

## 每项变更需要留下的材料

1. **变更请求**：目标用户任务、原因、来源需求 ID、涉及的页面／页面内控件／控件内功能／功能交互、原行为与拟议行为。
2. **边界**：新增、替换或取消的流程；正常、失败、权限、离线、恢复与时间边界；数据和原型模拟范围。
3. **设计差异**：页面路由、导航、状态、组件、token、响应式和动效。视觉表现变化也要给出前后截图。
4. **验证证据**：浏览器、视口、打开协议、测试时间、截图与运行日志；写明尚未覆盖的组合。截图应对应待评审的最终文件散列。
5. **审查与决定**：至少有视觉和交互／一致性两类结论。重大问题先关闭；产品负责人审阅实际候选后决定接纳、修订或不进入基线。

PR 使用 `.github/PULL_REQUEST_TEMPLATE.md`。CI 只校验文件与冻结账本完整性，不自动批准设计。

## Onboarding 内测候选

`prototype/onboarding-rebuild-candidate/` 是较早的四步资料录入候选，作为历史探索保留。最新的对话式集成候选是 `prototype/onboarding-chat-r30-candidate/`，使用独立浏览器存储键，包含单文件与分文件原型、需求/设计差异、参考图和验证材料；具体变化见 [R30 更新说明](updates/2026-10-22-onboarding-r30.md)。两者都不能自动代表 `prototype/current/` 已更新。

变更经 Wentao 明确确认后，以新 B-ID 保存完整设计账本、来源和原型快照，并在合入 `main` 后打新基线标记。绝不修改已有基线目录或重写历史收据。
