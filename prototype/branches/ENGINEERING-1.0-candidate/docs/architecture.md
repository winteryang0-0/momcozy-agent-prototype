# 工程与信息架构起点

## 当前页面分类

| 路由 | 页面职责 | 主要入口与返回 |
| --- | --- | --- |
| #/onboarding | 首次照护资料录入与后续修改 | 首访进入；首次完成或稍后设置后回首页，后续修改返回发起页 |
| #/home | 对话式首页、Today 智能提醒、常驻照护功能 | 左上侧栏仅有“我的”和“宝宝”；#/assistant 为兼容别名 |
| #/mine | 妈妈资料、妈妈记录、设备与同步 | 侧栏进入；记录页可返回来源页 |
| #/baby | 宝宝资料与宝宝照护 | 侧栏进入；使用与“我的”一致的页面逻辑 |
| #/records | 按日期与照护对象查看记录、新建记录 | 从“我的”或“宝宝”进入；右上角打开“我的”二级功能菜单 |

现有浮层承载记录编辑、资料编辑、筛选与设置；照护任务卡内联在对话时间线。Today 三张提醒卡支持循环切换和收缩后恢复。对话中的新任务可在旧任务未结束时再次触发。这些关系从 R27 继承，本轮没有重新定义。

## 数据和运行边界

- 浏览器存储键：momcozy-engineering-1.0、其 -conversations 派生键和 -onboarding 派生键。三个键与 R27 隔离。
- index.html 通过普通脚本按顺序加载 8 个应用职责文件，以及图标、动效、形象脚本；可在 file:// 下直接读取相对资源。
- 构建器读取 index.html 中的 CSS 与脚本标签顺序，内联本地图片，生成 Momcozy-final.html；预览器不再维护第二份写死的资源名单。
- design.json 的 framework、system、source 与上游 B-MOMCOZY-20261022-R27 快照逐项相同；本分支的 project 身份与 stage 改为独立 draft。

## 下一步候选修正

这些是待选择的工程议题，尚未改动 R27 的业务语义。

1. **导航与返回**：当前 hash 路由使用 replaceState，页面间的“返回来源”由多组变量维护。建议先画清首页、我的、宝宝、记录、浮层的返回矩阵，再统一导航状态；浏览器返回键的目标需作为产品规则确认。
2. **数据模型**：资料、记录、对话和录入草稿都由页面级状态直接管理。建议定义有版本的数据结构、字段校验与升级策略，再逐域迁移。多宝宝数据的对象归属需要先明确。
3. **跨日状态**：DAY 在页面加载时计算，长时间停留页面时依赖它的提醒和示例日期可能过期。建议把日期变化作为显式事件处理，并验证草稿和未完成任务不会丢失。
4. **任务生命周期**：媒体采集、任务卡、对话保存与多个计时器互相影响。建议建立可检查的任务状态转移表，覆盖再次触发、取消、后台中断与结果待确认。
5. **样式层级**：10 份 CSS 继承文件有明确加载顺序，后续版本可按 token、页面与组件整理。合并前后应逐状态截图比较，不凭代码相似度判断视觉等价。

## 后续每轮最低回归范围

首次录入和范围校验；首页侧栏到“我的”“宝宝”；从两处进入记录并新建、返回；Today 收缩、恢复、三卡循环；对话与重复任务触发；刷新后资料与对话恢复；明暗主题和窄屏。真实媒体、权限拒绝及同步模拟分别记录实际测试范围。
